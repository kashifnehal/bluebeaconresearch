### `PublicHeader.tsx` — added 2026-09-23 (#186 Phase 2)

Server component. Props: `{ badge: string }`. Renders the logged-out public-page chrome (logo → wordmark → badge on the left, "Terminal →" link on the right) used by `app/accuracy/page.tsx` and `app/status/page.tsx`. ### `MobileTabBar.tsx` — added 2026-09-23 (#186 Phase 3)

Client component, no props. `fixed bottom-0 left-0 right-0 z-40 md:hidden` — mounted once from `(dashboard)/layout.tsx` alongside `Sidebar`/`TopBar`. Five slots: FEED `/dashboard`, MAP `/map`, ALERTS `/alerts` (badge from `useUIStore.unreadCount`, same source `Sidebar` uses), WATCHLIST `/watchlist`, and a MORE button that calls `useUIStore.setMobileSidebarOpen(true)` — opens `Sidebar`'s existing off-canvas drawer rather than a second nav surface, so CALENDAR/BACKTESTING/SETTINGS/Help/Logout stay reachable without duplicating them. ### 3.3b `MarketImpactAssessment.tsx` (#143; #143 leftover 2026-09-20; #202 label 2026-09-25)
- **Purpose**: The event-detail / quick-view impact box, relabeled **MARKET IMPACT ASSESSMENT** (was PROJECTED IMPACT). ### 3.10 CalendarPage (`app/(dashboard)/calendar/page.tsx`) (2026-09-25)

### 3.11 `CategoryChips.tsx` (new, W2-FEEDUX/claude-278 4.2)

### 3.12 `SignalTable.tsx` (new, W2-FEEDUX/claude-278 4.1)
- **Purpose:** dense table view of the feed, toggled against the existing card/row list via a "Cards | Table" control in the "Recent Signal Stream" section header on the dashboard. Same `streamList` (already-loaded, already-filtered signals) backs both views — no separate fetch.
- Columns, all from fields already on the feed `Signal` object: Date, Event (title), Summary (first 120 chars + ellipsis — `truncateSignalSummary()`, `apps/web/lib/signal-table.ts`), Type (`eventCategoryLabel()` if set, else the raw `eventType`), Direction (reuses `CommodityChip.tsx` on the first `commodityImpacts`/`currencyPairImpacts` entry — the same arrow/color convention `SignalCard`/`SignalQuickView` already use — or "—" when a signal has none), Severity (`SeverityBadge`), Reports (`sourcesCount`), Topic (commodity/forex symbols, comma-joined). There is no sentiment field anywhere in BBR's schema — no Sentiment column was added.
- **Sortable columns:** Date, Severity, Reports (click the header, click again to flip direction) — client-side only, over the rows already loaded, via `sortSignalTableRows()` (`lib/signal-table.ts`): stable (ties keep original order), ascending/descending, rows with no usable date value always sort last regardless of direction. Default (no column clicked) is the feed's current order, unchanged. A "Sorting applies to loaded rows" line sits near the header so this isn't mistaken for a server-side re-sort.
- Rows are links to `/events/<id>` — same destination the existing stream rows already use.
- Horizontal scroll is contained inside the table's own wrapper (`data-testid="signal-table-scroll"`, `overflow-x-auto`) so the page itself never scrolls sideways at phone width.
- View choice (`"cards" | "table"`) is remembered in `localStorage` (`bbr_feed_view_mode`), read/written inside `try`/`catch` — renders "cards" by default when storage is unavailable (private mode, quota, SSR). Toggling never affects the existing infinite-scroll (`sentinelRef`)/"Load more" behavior or the Export CSV button (`lib/signal-csv.ts`), both of which sit outside this component and are unchanged.
